# Agent Note: dsh 0.2.1 上的 WorkBuddy

Status: implemented

[English](2026-10-20-workbuddy-0.2.1-migration.md) | 中文

## 问题

WorkBuddy 原本构建在 dsh 0.1.5 上：目录扫描式的 `agent-presets` 名单、浏览器里的 `agentPresetLaunch`，以及仍接受 `select` 的客户端 slot。dsh 0.2.1 用 `agent-preset-registry` 取代了旧名单，把 preset 声明移进 bundle 补丁文件，把浏览器开会话改为 `uiWorkspace.startSession(..., { agentPreset })`，并收紧了 Tool call 与 turn-tail 的节点形状。0.1.5 分支也无法加载 0.4.x 的 Skin Center，因为新包会等待 0.1.5 没有提供的 `configForms`。

## 决策

这个 fork 现在从 `0.2.1-rc.2` 的 `origin/master` 分支出发。自定义能力作为普通包与上游包并存：

- `packages/client/ui-workbuddy-mode`、`ui-workbuddy-scenarios`、`ui-workbuddy-shell` 保留 Ask/Plan/Craft、Office/Code/Design 场景 dock 与能力导航。
- `packages/finance/finance-local`、`packages/video/video-local`、`packages/video/xhs-local` 保留宿主机能力。
- `packages/client/ui-finance-view`、`ui-video-view`、`ui-xhs-view` 保留各自的成品卡片。
- `packages/bundle/web-app/presets/{finance,video,xiaohongshu}.patch.yml` 通过 `@deepseek-ai/dsh-agent-preset` 声明三个 preset。
- `packages/bundle/web-app/cordis.patch.yml` 挂载宿主机行、WorkBuddy 客户端行与三张卡片。场景选择现在调用 `ctx.uiWorkspace.startSession(undefined, { clearPreviousDraft: false, agentPreset })`；旧的 `agentPresetLaunch` 依赖已移除。

finance 的 turn-tail 席位现在接收 `PropsRuntime<'conversation.chat.turnTail'>` 并直接读取 `turn.turn`。权限投影改为 `PermissionSelection`（只含当前值），重命名后的 Medium 图标导出取代旧的数字导出。

## 验证

- `pnpm install --frozen-lockfile`
- `pnpm run build`：九个 gate 全部通过（native、host compiler/bundle/aggregate、desktop、client compiler/bundle/aggregate、web build）
- 对 `xhs-local`、`ui-xhs-view`、`ui-workbuddy-scenarios` 运行 `pnpm exec vitest run`
- 在 0.2.1 上启动 Web profile，并用 Playwright 验证：Island Life 皮肤通过 Skin Center 0.4.7 生效，WorkBuddy 导航存在，Finance、Video、Xiaohongshu 三个场景芯片都能以其命名 preset 开会话，且没有 console error。

## 限制

- 小红书链路已验证到会话创建与包挂载；还差一次真实视频帖子的端到端渲染与手动发布。
- 迁入的包保留原有测试与 fixture。上游 0.2.1 拥有生成的 remote/snapshot 表面；这个 fork 通过正常构建重新生成它们，而不是携带 0.1.5 的 snapshot。
