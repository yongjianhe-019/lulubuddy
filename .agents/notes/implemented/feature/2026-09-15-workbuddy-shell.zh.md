# Agent Note: WorkBuddy 外壳界面

Status: implemented

[English](2026-09-15-workbuddy-shell.md) | 中文

## Problem

WorkBuddy 的办公外壳用两个导航界面为用户定向：左侧能力栏（专家中心、技能市场、自动化、连接器、记忆）与右侧结果区（变更记录、浏览器预览、分享）。DSH 没有对应的外壳，而这些界面背后的能力散落在互不相关的包里，或者根本不存在。从 WorkBuddy 过来的用户无处查看这个外壳哪一半在这里存在、哪一半不存在；而一次把这些界面直接画成控件的朴素移植，会为 DSH 没有写入路径的能力提供按钮。

## Decision

[`ui-workbuddy-shell`](../../../../packages/client/ui-workbuddy-shell/README.zh.md) 把两个界面都渲染为 **只读索引**。

左侧界面是一个 `sidebar.panellist` 列表条目，其 `id` 是本包名；同一个 id 在布局根作用域、带键的 `main` 席位里键住一个能力索引主体，因此选择该行即选择该面板。右侧界面是一个通过 `ctx.sidebarRightTabs` 注册的标签类型，其主体与芯片标题以定义的 `id` 注册进带键的 `sidebar.right.pane.tab` 与 `sidebar.right.pane.tab.title` 席位。一个共享的呈现面板从模块常量绘制任意一组行，所有字符串都经 `workbuddy.shell` locale 命名空间到达它。

每一行陈述 WorkBuddy 界面与背后的 DSH 能力，`absent` 标记则标出 DSH 并不具备的界面。五行能力分别是：专家中心由 `packages/subagent` 与 Agent 预设支撑；技能市场由 `packages/skill` 的文件系统发现支撑，DSH 没有市场界面；自动化由 `packages/schedule` 支撑，DSH 没有写入界面；连接器由 `packages/mcp` 支撑；以及 **记忆 —— 它对应的能力 DSH 并不具备**。三行结果分别是：变更记录没有独立面板（改动以会话内的工具行与交付行呈现）；浏览器预览没有内置浏览器（右侧栏的文档预览可以只读渲染 HTML 文件）；以及 **分享 —— 同样对应 DSH 并不具备的能力**。

没有一行是控件。本包不声明 store、不声明注入的写入动词、也不挂点击处理器，因此它不可能渲染出无法行动的控件。它贡献的唯一可交互元素就是侧栏那一行本身，而它确实做了事：选择面板。

## Alternatives considered

**把界面移植成可用的控件。** 技能市场浏览器、自动化编辑器、浏览器预览和分享按钮会更贴近 WorkBuddy 的形态，但它们背后都没有 DSH 能力。构建它们意味着在一次以产品界面为范围的改动里凭空造出后端能力与写入路径；而把它们作为禁用态摆放出来，所陈述的东西并不比一行文字更诚实。

**把三个结果界面注册成三个标签类型。** 三个类型能让每个界面各有芯片、让用户一次打开一个，但一个标签类型等于宣称有东西可看。这三者都没有可支撑独立类型的 DSH 行为，结果会是三个死标签，而不是一个把三者都点名的索引。单一类型也让标签注册表不至于堆满只重复文案的条目。

**把能力索引放进会话的 main 席位。** 复用保留键 `conversation` 可以避免第二个主面板，但该键承载会话本身，并带有自己的会话绑定与子席位。`main` 之所以是带键的，正是为了让全局面板在旁边加一个键；新增键才是加法，替换会话则完全是另一个决定。

## Consequences

WorkBuddy 的外壳在这里作为导航存在，作为能力缺席。索引是静态文案，因此挂载或卸载 `packages/mcp`、`packages/skill`、`packages/schedule` 或 `packages/subagent` 不会改变任何一行的说法：映射靠手工维护，移除其中某个包的部署仍会读到该行由它支撑。记忆与分享的缺席标记是这份记录诚实的一半 —— 它们点名 DSH 尚未构建的东西，而不是把它藏在一个禁用控件后面。

本包没有任何部分会到达模型。它不新增工具、提示段落、会话事件或模型可见输入，也不读取任何会话数据，因此会话日志不变，这里也没有任何东西需要迁移。
